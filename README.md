# Decay Chain Explorer

Pick a radioactive isotope and scrub through time to see its decay chain: composition by atoms, mass or
activity, total activity in becquerels, and when every atom becomes stable. Mobile-first, works offline,
installable as an app.

No dependencies beyond Node 18+.

## Files

| Path | What it is |
|---|---|
| `index.html` | The whole app (page body, styles, solver, UI). Also published as a Claude Artifact as-is. |
| `nuclides.json` | Compact nuclide table the app loads (half-lives, masses, decay branches). |
| `data/iaea-ground-states.csv` | Raw IAEA LiveChart download that `nuclides.json` is built from. |
| `pwa/` | Web app manifest, service worker and Cloudflare headers. |
| `icons/` | App icons, generated by `tools/make-icons.js`. |
| `tools/` | Build and dev scripts (below). |
| `site/` | Build output to deploy. Not committed. |

## Commands

```bash
node tools/build-site.js        # build site/ for deployment
node tools/serve.js 8123 site   # preview the built site at http://localhost:8123
node tools/serve.js 8123        # preview index.html straight from the source folder
node tools/build-data.js        # rebuild nuclides.json from data/iaea-ground-states.csv
node tools/make-icons.js        # redraw the icons
node tools/check-solver.js      # check the solver against every chain and known physics
```

To refresh the nuclide data from the IAEA:

```bash
curl -A "decay-chain-explorer" -o data/iaea-ground-states.csv "https://nds.iaea.org/relnsd/v1/data?fields=ground_states&nuclides=all"
```

## Deploy

Both hosts are free, serve over HTTPS (required for installing and offline use) and rebuild on every push.
All paths in the app are relative, so it works at a domain root or under a sub-path like `/decay/`.

### GitHub Pages

1. Push this folder to a GitHub repository with `main` as the default branch.
2. In the repository: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Push to `main`. The workflow in `.github/workflows/pages.yml` builds `site/` and publishes it to
   `https://<user>.github.io/<repo>/`.

### Cloudflare Pages

Connected to Git (rebuilds on push):

1. Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git**, pick the repository.
2. Build command: `node tools/build-site.js` · Build output directory: `site`.
3. Deploy. The site appears at `https://<project>.pages.dev`.

Or upload directly from this machine without Git:

```bash
node tools/build-site.js
npx wrangler pages deploy site --project-name decay-chain-explorer
```

`pwa/_headers` makes Cloudflare re-check `sw.js` on every visit so updates arrive promptly.
GitHub Pages ignores that file; there, browsers check for a new service worker at most every 24 hours,
usually sooner.

## How updates reach installed copies

`tools/build-site.js` stamps the service worker with a hash of the app files. When anything changes,
the next visit installs the new version in the background and the following launch uses it.
